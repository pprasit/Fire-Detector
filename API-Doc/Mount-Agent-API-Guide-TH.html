1. ภาพรวม

Mount Agent เริ่มทำงานพร้อม fire-detector.service และเชื่อมคำสั่ง API เข้ากับ safety layer เดียวกับ Dashboard/ODriveMonitor เพื่อให้ motion limit, สถานะการเชื่อมต่อ Drive และเงื่อนไข enable ถูกตรวจในจุดเดียวกัน

Interfaceการเชื่อมต่อวัตถุประสงค์สถานะเริ่มต้น
Local Control InterfaceUnix domain socket
/run/fire-detector/mount-agent.sock		App ที่ทำงานในเครื่อง Mount เดียวกัน มี latency ต่ำและไม่ผ่าน network stack ภายนอกเปิด
Remote Device ProtocolMount เชื่อม TCP/TLS ออกไปหา Socket Receiverควบคุมและรับ telemetry จากศูนย์กลาง/LAN/Internet โดยไม่เปิด inbound port ที่ Mountปิดจนกว่าจะตั้งค่า credential
หลักสำคัญ: ทั้งสอง interface ใช้ JSON schema และชื่อคำสั่งเหมือนกัน แต่ Remote เพิ่ม TLS, device authentication และ command allowlist

Transport และ latency

  • Client บนเครื่อง Mount ควรเปิด Unix domain socket ค้างไว้หนึ่ง connection เป็นช่องทาง control ที่ overhead ต่ำสุดและไม่เปิด network port
  • งานระยะไกลใช้ TCP/TLS connection แบบ persistent ที่ Mount เชื่อมออกไปหา Receiver จึงไม่ handshake ใหม่ทุกคำสั่งและใช้ได้หลัง router/CGNAT
  • Local subscription ตั้งช่วงได้ 100–60,000 ms (สูงสุด 10 Hz); Remote telemetry ตั้ง telemetry_sec ได้ต่ำสุด 0.1 วินาที
  • WebSocket /ws/status ของ dashboard เป็น read-only status stream ไม่ใช่ Mount Agent control transport

TCP เป็น byte stream: client ต้องสะสมข้อมูลจนพบ newline และห้ามสมมติว่า recv() หนึ่งครั้งคือ JSON หนึ่ง message ควรใช้ connection เดิมตลอด lease/control session

2. Message framing และโครงสร้าง JSON

Protocol ใช้ NDJSON: หนึ่ง JSON object ต่อหนึ่งบรรทัดและปิดท้ายด้วย newline (\n) ข้อความหนึ่งมีขนาดไม่เกิน 64 KiB

Command

{
  "version": "1.0",
  "type": "command",
  "message_id": "cmd-0001",
  "action": "mount.get_status",
  "params": {}

3. Control lease

ในหนึ่งช่วงเวลาจะมีผู้ควบคุมได้เพียงรายเดียว คำสั่งอ่านข้อมูลและคำสั่งหยุดฉุกเฉินไม่ต้องใช้ lease

  1. เรียก control.acquire และเก็บ lease_id
  2. แนบ control_lease_id กับคำสั่งควบคุม
  3. เรียก control.renew ก่อน lease หมดอายุ
  4. เมื่อจบงาน เรียก control.release
{"version":"1.0","type":"command","message_id":"lease-1",
 "action":"control.acquire","params":{"lease_ms":5000}}

ช่วง lease ที่ระบบยอมรับคือ 500–30,000 ms หาก connection ปิด lease ของ session นั้นจะถูกปล่อยอัตโนมัติ

Fail-safe: mount.stop, mount.disable, axis.stop และ axis.disable เรียกได้โดยไม่ต้องมี lease เพื่อให้หยุดระบบได้เสมอ

9. การใช้งาน Local Control Interface

คำสั่งสำเร็จรูป

cd /home/pi/Public/Fire-Detector
.venv/bin/python scripts/mount_agent_client.py system.hello
.venv/bin/python scripts/mount_agent_client.py mount.get_status

ตัวอย่าง Python: connection เดียวพร้อม lease

import json, socket, uuid

s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect("/run/fire-detector/mount-agent.sock")

def call(action, params=None, lease_id=None):
    msg = {
        "version": "1.0", "type": "command",
        "message_id": str(uuid.uuid4()),
        "action": action, "params": params or {}
    }
    if lease_id:
        msg["control_lease_id"] = lease_id
    s.sendall(json.dumps(msg).encode() + b"\n")
    return json.loads(s.makefile("rb").readline())

lease = call("control.acquire", {"lease_ms": 5000})
lease_id = lease["result"]["lease_id"]
print(call("mount.get_status"))
# ตรวจพื้นที่และความพร้อมก่อนปลด comment คำสั่งควบคุม
# print(call("mount.enable", lease_id=lease_id))
# print(call("axis.goto",
#     {"axis":"altitude", "position_deg":10}, lease_id))
print(call("control.release", {"lease_id": lease_id}))
s.close()

Unix socket มี mode 660 และ Agent ตรวจ peer UID โดยอนุญาต root หรือ UID เดียวกับ service เท่านั้น

10. Remote Device Protocol

Mount เป็น TCP client เชื่อมออกไปหา Socket Receiver จึงเหมาะกับระบบที่อยู่หลัง router/CGNAT ลำดับการเชื่อมต่อคือ:

  1. TLS handshake และตรวจ CA/hostname (ขั้นต่ำ TLS 1.2)
  2. Mount ส่ง hello พร้อม Device ID และ capabilities
  3. Server ส่ง auth_challenge ที่มี nonce
  4. Mount ตอบ HMAC-SHA256 ของ device_id + nonce + timestamp
  5. Server ส่ง auth_result; เมื่อผ่านจึงเริ่ม command/telemetry
  6. Mount ส่ง heartbeat, telemetry และ reconnect แบบ exponential backoff เมื่อหลุด

ตัวอย่าง configuration

"mount_agent": {
  "local": {
    "enabled": true,
    "socket_path": "/run/fire-detector/mount-agent.sock",
    "mode": "660"
  },
  "remote": {
    "enabled": true,
    "host": "receiver.example.internal",
    "port": 15001,
    "server_name": "receiver.example.internal",
    "device_id": "NARIT-001",
    "ca_file": "/etc/fire-detector/ca.pem",
    "client_cert_file": "/etc/fire-detector/device.crt",
    "client_key_file": "/etc/fire-detector/device.key",
    "secret_file": "/etc/fire-detector/device.secret",
    "secret_env": "FIRE_DETECTOR_DEVICE_SECRET",
    "heartbeat_sec": 15,
    "telemetry_sec": 1
  }
}

Secret ต้องยาวอย่างน้อย 32 bytes และต้องมาจาก secret_file หรือ environment variable ห้ามเพิ่ม field secret ลงใน AppSetting.JSON

11. Camera Frame Ingest API

ระบบหลักไม่เปิดกล้อง Thermal หรือ Visible โดยตรง โมดูลกล้องภายนอกเป็นผู้เชื่อมต่อกล้องทั้งสอง แล้วส่งภาพ JPEG/PNG ที่ encode แล้วเข้ามาทาง HTTP API ระบบเก็บเฉพาะเฟรมล่าสุดของแต่ละกล้อง จึงไม่สะสมคิวเมื่อส่งประมาณ 60 FPS

วิธีแนะนำสำหรับ 60 FPS: Binary WebSocket

ห้ามส่ง byte array เป็น JSON array ของตัวเลขและไม่ควรใช้ Base64 สำหรับสตรีมความถี่สูง ให้เปิด connection เดียวไปที่ ws://192.168.1.105:8000/ws/camera-stream?role=producer&source=live แล้วส่งหนึ่ง binary message ต่อหนึ่งเฟรม:

[uint32 big-endian: ความยาว JSON header]
[JSON header แบบ UTF-8]
[JPEG/PNG bytes ที่เหลือทั้งหมด]
{"camera":"thermal","mime_type":"image/jpeg",
 "sha256":"64-lowercase-hex-characters",
 "metadata":{"producer_sequence":1234,
             "captured_at":"2026-08-11T10:30:00.000Z",
             "width":640,"height":512}}

byte ของภาพอยู่นอก JSON โดย WebSocket/TCP รักษาลำดับและส่งแบบ reliable, producer_sequence ใช้ตรวจช่องว่างจากต้นทาง และ sha256 ใช้ตรวจ payload ระดับ application

สำคัญ: ปิด WebSocket per-message compression (compression=None ใน Python) เพราะ JPEG/PNG บีบอัดมาแล้ว การบีบอัดซ้ำเปลือง CPU และทำให้อัตราเฟรมลดลงได้มาก
.venv/bin/python API-Doc/examples/04_publish_camera_binary_ws.py \
  --camera thermal --frame thermal-frame.jpg --fps 60

HTTP compatibility API

กล้องEndpoint

ตัวอย่าง curl

curl -X POST "http://192.168.1.105:8000/api/camera-stream/frame/thermal?source=live" \
  -H "Content-Type: image/jpeg" \

Response เมื่อรับสำเร็จ

HTTP/1.1 202 Accepted
Content-Type: application/json

{"ok":true,"camera":"thermal","source":"live","sequence":1234}

ตัวอย่าง HTTP แบบต่อเนื่อง

.venv/bin/python API-Doc/examples/03_publish_camera_frames.py \
  --host 192.168.1.105 --port 8000 \
  --camera thermal --frame thermal-frame.jpg --fps 60
  • Content-Type ต้องเป็น image/jpeg หรือ image/png
  • X-Camera-Metadata เป็น JSON object และไม่บังคับ
  • ขนาดแต่ละเฟรมไม่เกิน 16 MiB และ endpoint ไม่รับ raw thermal sensor array
  • รันอีก process ด้วย --camera visible เพื่อส่งกล้อง Visible พร้อมกัน
  • ตรวจสถานะที่ GET /api/camera-stream
  • ดูผลที่ /api/camera-mjpeg/live/thermal และ /api/camera-mjpeg/live/visible
สำหรับ production: โมดูลกล้องควรส่งภาพที่ encode เสร็จแล้วผ่าน LAN ที่เสถียร ตรวจ HTTP status ทุกเฟรม และ reconnect/retry แบบมี backoff เมื่อระบบรับภาพไม่พร้อม

12. Error codes ที่ควรรองรับ

Codeความหมาย/แนวทางจัดการ
UNSUPPORTED_VERSIONใช้ protocol version ไม่ตรง
INVALID_JSON, INVALID_MESSAGE_TYPEตรวจ JSON/framing/schema
MISSING_MESSAGE_IDสร้าง ID ที่ไม่ซ้ำให้ทุกคำสั่ง
MESSAGE_TOO_LARGEลด payload ให้ต่ำกว่า 64 KiB
RATE_LIMITEDลดเหลือไม่เกิน 20 commands/sec และทำ backoff
COMMAND_EXPIREDไม่ retry คำสั่งเดิม; สร้างคำสั่งใหม่หลังตรวจ state
CONTROL_LEASE_BUSYมี controller อื่นใช้งานอยู่ ห้ามแย่งควบคุม
CONTROL_LEASE_REQUIRED, CONTROL_LEASE_INVALIDacquire ใหม่และตรวจ session
ACTION_NOT_ALLOWEDคำสั่งไม่อยู่ใน Remote allowlist
INVALID_PARAMETERตรวจ parameter, motion limit และช่วงค่า
COMMAND_FAILEDอ่าน health/status ก่อน retry; หลีกเลี่ยง blind retry สำหรับ motion

13. Checklist สำหรับ App ที่ควบคุม Mount

  • อ่าน mount.get_status และตรวจ Drive/axis/limit ก่อน enable หรือ motion
  • ใช้ connection เดียวตลอด control session และรักษา lease
  • กำหนด expires_at สำหรับคำสั่ง motion จาก Remote
  • velocity ต้องมี watchdog timeout และส่งคำสั่งศูนย์ก่อนจบ session
  • มีปุ่ม Stop ที่เรียก mount.stop ได้โดยไม่ขึ้นกับ lease
  • ใช้ message ID ไม่ซ้ำ และจับ response ด้วย correlation_id
  • บันทึก audit log ฝั่ง Socket Receiver: user, device, action, parameters, result, timestamp
  • ไม่เก็บ secret/private key ใน source control หรือหน้าเว็บ
  • Remote server ต้องตรวจสิทธิ์ผู้ใช้ก่อน forward คำสั่งทุกครั้ง
  • ทดสอบด้วยความเร็ว/กระแสต่ำและพื้นที่ปลอดภัยก่อนใช้งานจริง
