1. Overview

The Mount Agent starts with fire-detector.service. Both API surfaces route commands through the existing ODriveMonitor safety layer, so configured motion limits, drive availability, and enable conditions are enforced consistently.

InterfaceTransportPurposeDefault
Local Control InterfaceUnix socket
/run/fire-detector/mount-agent.sock		Low-latency control by applications running on the Mount computer.Enabled
Remote Device ProtocolOutbound TCP/TLS connection to a Socket ReceiverCentral control and telemetry without exposing an inbound port on the Mount.Disabled until credentials are configured
Wire format: Both interfaces use protocol 1.0 and newline-delimited JSON (NDJSON). Each message must be no larger than 64 KiB.

Transport and latency

  • On-device clients should keep one persistent Unix domain socket open. It is the lowest-overhead control path and exposes no network port.
  • For remote operation, the Mount keeps one persistent outbound TCP/TLS connection to the Receiver, avoiding a handshake per command and working behind routers/CGNAT.
  • Local subscriptions support 100–60,000 ms intervals (up to 10 Hz). Remote telemetry supports a minimum telemetry_sec of 0.1 seconds.
  • The dashboard WebSocket at /ws/status is a read-only status stream, not a Mount Agent control transport.

TCP is a byte stream: clients must buffer until a newline and must not assume that one recv() call contains exactly one JSON message. Keep the same connection for the complete lease/control session.

3. Control Lease and Fail-Safe Behavior

Only one client may own control at a time. Acquire a lease, attach its ID to control commands, renew it before expiry, and release it when finished.

{"version":"1.0","type":"command","message_id":"lease-1",
 "action":"control.acquire","params":{"lease_ms":5000}}
  • Lease range: 500–30,000 ms.
  • The session lease is released when its connection closes.
  • mount.stop, mount.disable, axis.stop, and axis.disable do not require a lease.
  • Non-zero velocity commands require command_timeout_ms from 100–5,000 ms. The watchdog commands zero velocity when updates stop.

6. Python Example 1 — Status and Telemetry

Complete source: API-Doc/examples/01_local_status_and_telemetry.py. It is read-only and safe to run while the service is active.

with socket.socket(socket.AF_UNIX, socket.SOCK_STREAM) as client:
    client.connect("/run/fire-detector/mount-agent.sock")
    stream = client.makefile("rwb")
    send(stream, command("mount.get_status"))
    print(receive(stream))
    send(stream, command("subscribe", {
        "topics": ["axis.telemetry", "sensor.status"],
        "interval_ms": 500
    }))
    print(receive(stream))       # subscription response
    for _ in range(10):
        print(receive(stream))   # telemetry events

.venv/bin/python API-Doc/examples/01_local_status_and_telemetry.py

7. Python Example 2 — Safe Axis Control

Complete source: API-Doc/examples/02_safe_axis_control.py. Motion is locked by default with ALLOW_MOTION = False. The example reads status, acquires a lease, enables Altitude, performs a low-speed Goto, and always executes stop/disable in finally.

lease = mount.call("control.acquire", {"lease_ms": 5000})
lease_id = lease["result"]["lease_id"]
try:
    mount.call("axis.enable", {"axis": "altitude"}, lease_id)
    mount.call("axis.goto", {
        "axis": "altitude",
        "position_deg": 10.0,
        "max_velocity_deg_per_sec": 2.0
    }, lease_id)
finally:
    mount.call("axis.stop", {"axis": "altitude"})
    mount.call("axis.disable", {"axis": "altitude"})
    mount.call("control.release", {"lease_id": lease_id})
Before enabling motion: clear the working area, station an operator at the Mount, verify configured limits and direction, start with low current/speed, and provide an independent emergency stop.

8. Remote Device Protocol and Security

  1. The Mount opens an outbound TCP connection.
  2. TLS validates the CA and hostname; TLS 1.2 is the minimum.
  3. The Mount sends Device ID and capabilities.
  4. The receiver sends a nonce challenge.
  5. The Mount responds with an HMAC-SHA256 signature over device ID, nonce, and timestamp.
  6. After authentication, heartbeat, telemetry, and allowlisted commands begin.
"remote": {
  "enabled": true,
  "host": "receiver.example.internal",
  "port": 15001,
  "server_name": "receiver.example.internal",
  "device_id": "NARIT-001",
  "ca_file": "/etc/fire-detector/ca.pem",
  "client_cert_file": "/etc/fire-detector/device.crt",
  "client_key_file": "/etc/fire-detector/device.key",
  "secret_file": "/etc/fire-detector/device.secret",
  "heartbeat_sec": 15,
  "telemetry_sec": 1
}

The device secret must contain at least 32 bytes. Store it in a permission-restricted file or environment variable, never directly in AppSetting.JSON or source control.

9. Camera Frame Ingest API

The main system no longer opens the Thermal or Visible camera directly. An external camera module connects both cameras and sends already encoded JPEG/PNG frames to the HTTP API. The relay retains only the newest frame per camera, preventing queue latency at approximately 60 FPS.

Recommended at 60 FPS: binary WebSocket

Do not serialize image bytes as a JSON integer array and do not Base64-encode high-rate frames. Open one persistent connection to ws://192.168.1.105:8000/ws/camera-stream?role=producer&source=live and send one binary message per frame:

[uint32 big-endian JSON header length]
[UTF-8 JSON header]
[all remaining bytes: encoded JPEG/PNG]
{"camera":"thermal","mime_type":"image/jpeg",
 "sha256":"64-lowercase-hex-characters",
 "metadata":{"producer_sequence":1234,
             "captured_at":"2026-08-11T10:30:00.000Z",
             "width":640,"height":512}}

The image bytes remain outside JSON. WebSocket/TCP provides ordered reliable delivery, producer_sequence identifies source-side gaps, and optional sha256 verifies application payload integrity.

Important: Disable WebSocket per-message compression (compression=None in Python). JPEG/PNG is already compressed; recompressing every frame wastes CPU and can substantially reduce frame rate.
.venv/bin/python API-Doc/examples/04_publish_camera_binary_ws.py \
  --camera thermal --frame thermal-frame.jpg --fps 60

  • Content-Type must be image/jpeg or image/png.
  • Optional X-Camera-Metadata must be a JSON object.
  • Each frame is limited to 16 MiB. Raw thermal sensor arrays are not accepted.
  • Run a second process with --camera visible for the Visible feed.
  • Check GET /api/camera-stream and view the MJPEG paths under /api/camera-mjpeg/live/....
Production guidance: Publish pre-encoded frames over a stable LAN, inspect every HTTP status, and reconnect or retry with backoff when the receiver is unavailable.
